# v1.1.0 更新与验收记录

发布日期：2026-10-29。Windows 便携包、源码包及资源包随 GitHub v1.1.0 发布。

## 功能

- 修复旧立绘路径覆盖新资源导致封面缺失、启动时启用状态未同步，以及压缩包／文件夹导入名称框被禁用。
  检查器修改名称后表格立即同步，不必刷新。
- 模组预览面板、图片放大窗口和模组总览工具栏均提供“已启用模组画廊”。
  模组总览和角色详情均在当前页面切换，点击“返回”回到原列表，不弹出画廊窗口。
  画廊显示所有已启用模组及预览，无图时显示占位；每张卡片可快速开关，左右方向键选择、空格切换。
  禁用后的卡片暂时保留，便于重新启用，点击画廊刷新后重新筛选；切换失败时展示错误并保持真实状态。

- 保留现有 54 套角色装甲；每套装甲提供默认皮肤。
- 依据 [BWIKI 时装一览](https://wiki.biligame.com/sonw/时装一览) 收录 116 套中英时装名称。
  该页面注明更新至游戏 3.8；这是可追溯的 Wiki 快照，不保证覆盖其后所有时装。
  数据位于 `snowmm/assets/catalog/skins.json`，可用 `python tools/fetch_skins.py` 刷新。
- 详情页保留装甲切换，并新增皮肤切换。列表、文件视图、启用全部、禁用全部、只启用所选
  均作用于当前皮肤；“禁用该角色”仍处理这套装甲下的所有皮肤。
  切换皮肤是管理分类，不会修改游戏中的皮肤选择或自动启停其他皮肤。
- 添加模组时默认选择详情页当前皮肤；可在导入对话框修改，也可在右侧检查器中移动已有模组。
  皮肤选择会持久化到数据库，旧记录默认属于默认皮肤。
- 主界面新增“基地”和“杂项”两张独立卡片；支持相同导入、启停和预览操作。
  两类不做多模组启用及重复路径记录检查，文件缺失仍提示。
- 普通角色的多模组启用检查改为按“装甲 + 皮肤”分组，不同皮肤互不提示重复。

## 英文目录

```text
mods/
  katya-rhapsody/                    # 默认皮肤
    Skin_100_P.pak
    Skin_100_P.utoc
    floral-flutter/                  # 花间蝶踪
      Floral_100_P.pak.disabled
  Base/
  Miscellaneous/
```

资源文件、属性目录、历史代码归档也改为英文路径。角色和皮肤名称仍按语言显示。
用户自行选择的游戏／模组根目录不会被改名；应用生成的相对目录和包文件名使用 ASCII。
任意中文模组文件名无法可靠自动翻译，因此使用稳定标识，例如 `mod-<hash>_100_P.pak`，
保留原始显示名以及 Unreal 原有 `_100_P` 后缀。

旧目录升级步骤：

1. 保留原 `%APPDATA%/SnowMM` 数据并升级应用。
2. 启动时会自动检查选定的模组目录，识别中文一级目录及 0.2.x 的“角色/装甲/服装”三级目录。
3. 发现旧文件后先在数据库旁生成 `data-before-compatibility-*.json` 快照，再自动转换包和对应记录。
   可识别的 Wiki 皮肤保留归属，未知旧皮肤归入默认皮肤；已有英文皮肤目录不会被摊平。
4. 选择新目录、扫描及 F5 刷新也会执行检测。文件锁定等失败会显示原因；可重试其余包。
   没有待修复项目时不会重复创建备份，未知角色目录和非模组文件不自动移动。

迁移保留禁用状态，`.pak/.utoc/.ucas/.sig` 成组移动，碰撞时统一加序号。
每组移动失败会尝试回滚。数据库快照不是整套模组文件备份；不要把旧快照单独覆盖到已迁移的目录。
未知文件夹及与模组无关的文件保留原位。

## 解压导入

文件选择器和拖拽均接受 ZIP、7z、RAR。解压到独立临时目录，递归识别包，
同名配套文件一并导入；同一压缩包的多个包分别登记。原压缩包保留，临时数据自动清理。

ZIP 使用 Python 标准库，7z 使用 py7zr。RAR 使用 rarfile，并识别 PATH 和常规安装位置中的
WinRAR／7-Zip。Windows 自带 tar 可作为后备，但不能解开所有 solid RAR；缺少合适后端时提示安装。
加密包、分卷包、嵌套压缩包暂不支持，也不执行包内程序。

在解压前拒绝越界路径、盘符、符号链接／重定向、重复包路径及 Windows 保留名称。
单压缩包最多 20,000 个条目、声明解压总量最多 8 GiB；超出时整包拒绝。
