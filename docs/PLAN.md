# SnowMM 重构大纲（JASM 风格）

> 历史设计记录；v1.0.0 的最终发布说明见 [RELEASE.md](RELEASE.md)。
> 54 张无字角色图及新多尺寸图标已随包发布，英文名称仅改变显示，不改变目录。

> 目标：把 0.2.2 的单文件 PyQt5 工具，重构成一个**分层、可测试、更现代**的桌面应用。
> 原实现完整保留在 `snow_mod_manager/`（历史版本），新实现位于 `snowmm/`。

## 1. 技术选型

| 方面 | 原来 (0.2.2) | 现在 (1.0) | 原因 |
| --- | --- | --- | --- |
| GUI | PyQt5，单个 1333 行文件 | PySide6 (Qt6)，分层包 | Qt6 更现代，PySide6 是官方绑定，许可证对开源/闭源都友好 |
| 结构 | 单文件 + translations.py | `core`（无 Qt）+ `ui`（Qt） | 业务逻辑可单测、可换前端 |
| 数据 | `~/.snowbreak_mod_manager/projects.json` | `%APPDATA%\SnowMM\data.json`（原子写入） | 规范化位置、写盘安全、带 schema 版本 |
| 磁盘布局 | `<角色>/<装甲>/<服装>/` 三级 | `<角色-装甲>/` 一级 | 尘白的实际挂载单位是角色，三级目录只是历史包袱 |
| 角色来源 | 内置种子名单 | **内置立绘库**（`snowmm/assets/characters/<属性>/*.png`） | 有图才有角色，主界面数量与图片严格一致（固定 54 位） |
| 主题 | 两份长 QSS | Theme 数据类 + 模板生成 | 颜色集中管理，一处改动全局生效 |
| 图标 | 1 个 svg | 内联 SVG 图标集 + 打包的属性图标 | 不需要二进制资源，跟随主题变色 |
| 交互 | 大量模态弹窗 | Toast + 卡片 + 网格 | 现代桌面应用的观感 |

## 2. 目录结构

```
snowmm/
  core/             # 不依赖 Qt，可单元测试
    paths.py        # 用户数据目录、资源路径、属性常量
    settings.py     # 用户偏好（路径/主题/语言/行为）
    models.py       # Mod 数据类（含 0.2.x 兼容解析）
    store.py        # JSON 数据库（原子写、schema 版本、损坏备份）
    catalog.py      # 角色图鉴（立绘库 + 内置注解 + 用户注解合并，名单不可扩张）
    manager.py      # 导入 / 启用禁用 / 扫描 / 冲突审计 / 移动
    migrate.py      # 0.2.x → 1.0 数据迁移、三级目录 → 一级目录转换
    shell.py        # 打开目录、打开链接、启动游戏
  ui/
    theme.py        # 明/暗主题 token + QSS 模板
    icons.py        # 内联 SVG 图标
    imaging.py      # 立绘/预览图缓存、封面裁剪、无图时生成渐变占位图
    context.py      # AppContext：页面共享的数据与服务
    main_window.py  # 侧边栏 + 顶栏 + 页面栈 + 拖拽导入 + Toast
    dialogs.py      # 导入对话框、角色资料编辑器
    widgets/        # 卡片、属性徽章、标签、搜索框、空状态、Toast、表格、检查器、流式网格
    pages/          # 角色概览 / 角色详情 / 模组总览 / 冲突检查 / 设置
  assets/
    cbjq.ico        # 应用图标
    elements/       # 5 个 40x40 属性图标（高热/低温/电击/动能/特异）
    characters/     # 内置立绘库：<属性>/<角色-装甲>.png（54 张）+ 同名属性图标
    catalog/        # characters.json：英文名 + 定位注解
docs/               # 重构大纲 + 界面截图（tests/screenshots.py 生成）
tests/              # 核心单测 + 离屏 UI 冒烟 + 截图工具
tools/              # 打包脚本 + 可选的 wiki 抓取脚本
```

## 3. 数据模型

```python
Mod:       name, file(启用路径), character("角色-装甲"), author, source_url,
           note, preview, added_at, tags, size      # enabled 由文件系统推导，不落盘
Character: name("角色-装甲"), name_en, element, role, portrait, user_defined
```

* 磁盘布局：`<模组目录>/<角色-装甲>/xxx_100_P.pak`，例如
  `<模组目录>/凯茜娅-狂诗/Black Robe_100_P.pak`。
* **角色全名是唯一键**：图鉴、目录名、`Mod.character` 三者完全一致。
  图鉴里的 `name` 直接就是文件夹名，省掉了任何映射表。
* 立绘文件名同样是角色全名：`snowmm/assets/characters/低温/凯茜娅-狂诗.png`。
* 名单**只由立绘库决定**：数据库里的角色注解只能补充已有条目，改名或新增都不会扩张名单。

## 4. 对照 JASM 的功能映射

| JASM | SnowMM | 说明 |
| --- | --- | --- |
| 左侧导航（角色/NPC/武器/…） | 角色概览 / 模组总览 / 冲突检查 / 设置 | 只保留尘白实际需要的页面 |
| 角色头像网格 + 模组数量角标 | ✅ 同款网格，含收藏、有模组筛选、**属性分类** | 响应式列数（128–208px 之间自动取值），数量以立绘库为准 |
| 角色详情三栏（立绘 │ 列表 │ 模组详情） | ✅ 立绘 + 统计 │ 模组表 / 文件夹 │ 检查器 | 检查器可编辑名称/作者/来源/备注/预览图；角色全名只在角色页显示，不重复出现 |
| 元素图标筛选 | ✅ 属性徽章 + 属性筛选条（图标来自立绘库同名图标） | 不编造游戏数据，图鉴字段留空即不显示 |
| 装甲切换 | ✅ 左栏下拉切换同一角色的其他装甲 | 代替旧版的「皮肤」下拉 |
| 启用勾选列 + 表格 | ✅ `启用` 复选框列 + 右键菜单 + 批量操作 | 「只启用所选」一键关掉同角色的其他模组 |
| 一键禁用该角色全部模组 | ✅ 角色详情左栏 | |
| 启动游戏 / 打开模组文件夹 | ✅ 顶栏 | 游戏程序可在设置里指定 |
| 模组预设 | ❌ 已移除 | 使用频率低，用户要求删除 |
| 模组排序 | ❌ 已移除 | 网格固定按属性 + 角色名排序 |
| 详情右侧 ini / 按键提示 | ❌ 不做 | 尘白的模组是 `.pak`，包里没有 ini |
| 添加模组按钮 | ✅ 只在角色详情页 | 首页/模组总览不再放按钮，导入目标永远是当前角色 |
| 剪贴板图片 | ✅ 检查器与导入对话框都有「粘贴图片」 | 截图后不用先存盘 |

## 5. 关键实现细节

* **启用/禁用**：把文件重命名为 `*.disabled`（游戏只挂载 `.pak`）。同一 stem 的 `.utoc/.ucas/.sig` 会一起改名，避免只改一半导致模组失效。
* **导入**：支持单文件与整个文件夹；文件名的后缀不做要求，重名自动插在已有后缀之前（`same (2)_100_P.pak`），有后缀的文件依旧能被挂载。导入后按需写入预览图（本地文件或剪贴板图片）。
  压缩包（`.zip/.7z/.rar`）暂时**停用**：解包曾出现中文文件名与路径穿越问题，先保证普通 pak 添加的体验，修好后按原设计加回（原实现见 git 历史）。
* **扫描目录**：只收编「一级子目录名在名单内」的 `.pak/.utoc`；名单外的目录与散落在根目录的文件一律不动，避免凭空长出角色卡片。
* **冲突检查**：同角色多启、文件缺失、记录指向名单外的角色、重复记录，均可一键修复。
* **目录转换**：设置页的「转换目录结构」会把旧的 `<角色>/<装甲>[/<服装>]/` 摊平成 `<角色>-<装甲>/`，碰撞时自动加序号，空目录自动清理。
* **迁移**：首次启动若检测到 `~/.snowbreak_mod_manager/projects.json` 且新库为空，自动迁移记录与预览图（幂等）；设置页也可手动触发。

## 6. 验收与测试

```bash
python -m unittest discover -s tests -t .   # 57 项核心与资源检查
python tests/smoke_ui.py                    # 离屏 UI 冒烟：名单/属性筛选/详情/装甲切换/开关/改归属/滚轮/主题/i18n
python tests/screenshots.py                 # 生成 docs/screenshots/ 里的页面截图（有显示器时直接抓真实窗口）
python -m ruff check .                      # 静态检查
```

冒烟测试里的回归断言对应三个真实翻车点：

1. 反复导航 / 刷新**不能**产生新的顶层窗口——此前每张卡片都会被 `setParent(None)` 提升成独立弹窗。
2. 网格反复重排后宽度必须仍然小于窗口宽度——`minimumSizeHint` 曾随列数增长，把网格从 600px 撑到 11000px 后爆栈。
3. 滚轮**不能**改动没有焦点的文本框 / 下拉框。
