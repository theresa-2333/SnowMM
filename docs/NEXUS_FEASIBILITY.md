# Nexus Mods 在线下载可行性评估

评估日期：2026-10-27。仅调研与设计，没有新增网络客户端、账号配置、下载按钮或协议注册。

结论：技术上可行，建议下一个独立版本先做“指定 Mod 链接 → 选择文件 → 下载 → 本地归类导入”。
先完成账号接入和下载闭环，再考虑站内搜索和推荐流。当前解压、包分组、皮肤归属逻辑可以复用。
以下开发量为基于现有代码的工程估计，不包含 Nexus 审核等待时间。

## 已核实的前提

| 事项 | 对本项目的影响 | 依据 |
| --- | --- | --- |
| 游戏专区存在 | 使用 `snowbreakcontainmentzone` 作为专区域名；正式接入时再通过 API 确认游戏信息 | [Nexus 游戏专区](https://www.nexusmods.com/snowbreakcontainmentzone/mods/top?offset=0) |
| API 身份验证 | 请求携带用户密钥和应用标识；SSO 可通过 WebSocket 返回密钥，不必保存用户密码 | [官方 API 客户端说明](https://github.com/Nexus-Mods/node-nexus-api)、[官方 SSO 示例](https://github.com/Nexus-Mods/sso-integration-demo) |
| 公开应用需注册 | 个人 Key 可用于个人用途和测试；面向公众的正式版本需提交测试构建并注册应用，取得应用 slug | [API 使用政策](https://help.nexusmods.com/article/114-api-acceptable-use-policy) |
| 下载权限有分支 | 官方 API 客户端注明非 Premium 用户需从网站下载动作取得 key／expires 参数 | [官方客户端 getDownloadURLs](https://github.com/Nexus-Mods/node-nexus-api/blob/master/src/Nexus.ts) |
| 请求受限 | 读取响应限额和重置时间，遇到 429 暂停；避免固定写死旧配额 | [官方限流说明](https://help.nexusmods.com/article/105-i-have-reached-a-daily-or-hourly-limit-api-requests-have-been-consumed-rate-limit-exceeded-what-does-this-mean) |

权限分支来自官方客户端源码，尚未以本项目的免费或 Premium 账号实际验证。
因此不承诺“所有账号都能在应用内直接自动下载”。免费用户应先打开网站完成下载动作，
再通过 `nxm://` 回调进入管理器；未接入回调时提供手动下载压缩包后导入的路径。

## 建议的第一阶段范围

1. 只接受当前游戏的 Nexus Mod URL，读取 Mod 信息和可下载文件列表，展示文件版本与作者说明。
2. 用户主动选择文件和目标装甲／皮肤；未知归属落入“杂项”或待归类队列。
   Nexus 类别不等于游戏皮肤，不能仅凭标题自动确定，也不应批量启用压缩包中的所有变体。
3. 单独的下载任务负责超时、取消、重试、进度、临时 `.part` 文件、大小／哈希验证。
   下载完成再调用 `ModManager.import_paths()`；导入成功后才清理下载缓存。
4. 使用后台线程或 Qt 网络事件处理，下载和大文件解压均避免占用 UI 线程。
5. 在记录中保存专区、Mod ID、File ID、版本、文件摘要及原始来源 URL，方便后续更新检查。
6. 密钥存入 Windows Credential Manager 等系统凭据库；日志过滤密钥、SSO token、
   下载签名及有效期参数。API 凭据仅发送给 API 域名，不随 CDN 请求转发。

上述内容是本项目的方案建议，不是已经实现的接口或 Nexus 对未来注册的承诺。

## 后续阶段

| 阶段 | 内容 | 工程估计 |
| --- | --- | --- |
| 小范围验证 | 测试用 Key、单链接信息查询、Premium／免费权限验证、单文件下载和导入 | 2–4 个工作日 |
| 可公开使用的最小版本 | 应用注册、SSO、凭据存储、失败恢复、下载列表与取消、打包及回归 | 另需 4–7 个工作日，审核另计 |
| 浏览器回调与更新检查 | `nxm://` 接收、单实例转发、过期参数处理、版本关联和更新提示 | 另需 3–5 个工作日 |
| 站内搜索／浏览 | 评估官方 REST／GraphQL 搜索能力、分页缓存、内容筛选和展示要求 | 待最小版本验证后估算 |

`nxm://` 是系统级协议，可能已由 Vortex 等管理器占用。应让用户主动设置关联并能恢复，
解析后只接受正确的游戏、数值 ID 和允许的参数，不能拼接到 shell 命令。

## 发布前必须验证的项目

- 完成 Nexus 应用注册，并使用注册应用提供的授权方式；不把开发者个人 Key 随应用分发。
- 对免费与 Premium 分别验证可用流程、过期链接、用户取消授权及 401／403／429。
- 大文件中断恢复、磁盘不足、取消后的临时文件清理、恶意归档和多皮肤变体处理。
- 检查已删除、隐藏、受限内容、作者安装要求和依赖；账号无权访问时明确提示。
- 复核网络环境可达性；本次仅核实公开文档和源码，未携带账号请求 API 或 CDN。
- 核实 Python 包和 Windows 冻结构建中的网络、凭据库依赖，保持离线管理功能可独立使用。

优先级建议：值得做，先做链接下载闭环。完整站内浏览的维护成本更高，暂不作为第一阶段目标。
